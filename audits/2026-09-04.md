## Compatible branch-safety recommendation

Enable force-push and deletion prohibitions for `main` without requiring PRs; these fit the current fast-forward automation. Before introducing required PRs or required status checks, prove an explicit writer bypass using an appropriate GitHub App and test its exact permission/actor behavior. Do not assume the built-in Actions token is a selectable bypass actor. Human changes should retain the existing actionlint, Ruff, and test checks; workflow path filters also need review before making these universally required.

DCO sign-off is present in the commits, including automated writers, but it is not a cryptographic signature. Requiring signed commits would need a separately validated signing mechanism for the bot. Administrative activation was deliberately left outside this coding audit; no speculative ruleset configuration was committed.

Worthwhile next work is activating that tested branch-safety policy. Windows CLI collection is optional until its installation, runtime, and runner reliability are validated. The remaining ambiguous public/internal feature classification requires stronger upstream evidence, not a local heuristic.
