## Failure-policy decision

**Retain strict blocking behavior.** No timeout increase, URL exception, advisory
classification, or degraded canonical commit was introduced.

`preserve_missing_sources` prevents absent manifest entries in a preserved family
from being deleted, and partial discovery already avoids confirming removals. It
does not by itself identify which child last observed a path, validate an individual
child's cached baseline, preserve a separately identifiable complete web snapshot
while other children update content, or change release-only eligibility safely.
Using the old union as if it were a complete child observation would invent evidence.

A future degraded policy needs all of the following before accepting transport
failures: a verified complete child baseline, integrity checks for retained bytes,
explicit current-versus-retained coverage, no incomplete-discovery removals, a
separately identifiable complete web snapshot, stable repeat-run output, and
release-only reuse rules that cannot promote partial diagnostics to completeness.
The new child observations make that investigation possible once a complete run
succeeds; they do not confer degraded eligibility themselves.

Root-index failure, unavailable discovery without a verified baseline, malformed
source content, provenance disagreement, unsafe removal, and generation/integrity
failures must remain blocking. Existing source failures now carry explicit
`severity: blocking` in current-attempt diagnostics. Informational tombstones remain
subject to the existing positive HTTP evidence rules.

## Security and reproducibility review

Existing docs/release-state/feature direct writers retain their shared concurrency,
stale-base checks, and explicit push credentials. Actions remain pinned to immutable
40-character SHAs. The version helper now requests PR write only in its writer job
and disables persisted checkout credentials. No settings, secrets, or permissions
outside committed workflow files were changed.

CLI help/prompt collection uses temporary homes/workspaces and an environment
allowlist; inherited GitHub tokens are stripped. Feature introspection sets a
temporary `CODEX_HOME` and strips GitHub tokens, but its broader inherited environment
and real `HOME` are less isolated than help/prompt collection. No leak was observed;
consolidating that boundary is a functional follow-up, not evidence of full isolation.

Learn/developer page content types and malformed sitemaps are checked. Redirects are
recorded, but there is no general final-host allowlist. Output paths reject absolute
paths and `..`; existing symlink-parent containment is not separately hardened.
Current outputs passed containment/hash checks. These limits should be considered
before broadening source trust or allowing cached partial transactions.

Source-build failure rejection and failed release generation preserve canonical
bytes in fixtures. The writer publishes only a successful Git transaction. This is
not a claim of filesystem crash atomicity: canonical file writes are sequential,
and rollback after an unexpected write-time failure is not established. Full-sync
manifest loading also rebuilds invalid JSON rather than universally failing closed;
release-only cached file hashes are independently checked. Further transaction
hardening is appropriate before adding degraded commits.

Runtime requirements pin three direct packages, development requirements two;
transitive versions remain resolver-selected. A fully hashed cross-platform lock
could improve reproducibility, but needs coordinated Linux/macOS Python 3.14 wheels,
updates, and Renovate ownership. No dependency-resolution incident was established;
that separate change was deferred rather than mixed into outage handling. No package
manager migration was attempted.

## Deferred work and manual recommendations

- Keep child timeouts blocking until complete child contributions and retained
  snapshot integrity are demonstrable. Retry live strict validation after upstream
  recovery; do not reinterpret the unchanged canonical report as current web health.
- Broader coverage/lint/formatting/contributor work is outside the owner's narrowed
  scope. The trial found 444 I/UP/B diagnostics, mostly annotation modernization,
  and formatting would touch 15 files. No blanket cleanup was retained.
- Large `main`/capability-inventory decomposition, redirect trust policy, stronger
  feature-process isolation, symlink containment, write rollback, and transitive
  locking remain separate, testable functional follow-ups.
- Recommended out of band: prohibit force pushes and branch deletion on main while
  preserving the existing fast-forward direct writers. Do not require PR-only writes
  until a suitable explicit writer bypass actor is tested. Do not assume
  `GITHUB_TOKEN` can be selected as a ruleset bypass actor.
- If automated VERSION PR creation is desired, a maintainer may enable GitHub's
  “Allow GitHub Actions to create and approve pull requests” setting. Otherwise the
  helper's single tracking issue identifies the exact branch for a human-opened PR.
  Repository releases remain useful as intentional tooling milestones; their version
  is independent of the mirrored upstream CLI release.

No administrative recommendation was applied. Every implementation commit created
by the assistant has a DCO sign-off; this is not a claim of cryptographic signing or
of sign-off on owner-generated merge commits.
